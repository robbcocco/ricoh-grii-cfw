# gr2_cfw — agent manual

Custom firmware for the Ricoh GR II (fw 3.00). User manual: `README.md`. Loader and release-firmware design: `loader/flash/README.md`. Emulator: `tests/emu/README.md`. This repository is standalone: reverse-engineering notes, test records and plans are kept outside it (comments cite them as "finding N"); never add them here and never reference paths outside this repository.

## 1. Workflow
- **Build and test** (from this directory):
  ```sh
  make            # all variants: bin/{release,debug,rom}/gr2_{cfw,main}.bin (rom = release logging + CFW_ROM: the CFW on A:)
  make test       # ruff + ISA audit + emulator (all variants) + loader and release .frm checks; CI runs this with WERROR=1
  make rom        # release firmware dist/rg2_v003_cfw.frm + manifest + independent check
  make dist       # dist/gr2_cfw-v<VERSION>.zip (official) and -debug.zip (developer), SHA256SUMS.txt, RELEASE_NOTES.md
  make emu EMU_ARGS="--render /tmp/emu_out"   # screen PNGs: look at them after UI changes
  ```
  `make fw` (pulled in by `emu`/`loader`/`rom`) extracts the stock firmware into `fw/`. Host tools: `pip install -r requirements-dev.txt`. `make test` must pass before `make dist`.
- **Never** touch an SD card (`/Volumes/*`), flash anything, or run code on a camera. Hardware tests are done by a person with the kits from `make flash-kit` (`dist/flash/<step>/STEP.md`, written by `scripts/flash_kit.py`) after the maintainer's pre-flight safety check.
- **Development on hardware** uses the debug loader (`dist/rg2_v003_loader.frm`, in the debug zip): it loads the CFW from the card's `cfw/` folder, so new builds need no reflash. Every feature is tested there before it goes into the release firmware.
- **Tests** (`tests/emu/`): add a check when a bug could plausibly come back (e.g. palette flash, patch restore). Prove a new check fails without the fix. No checks of wording or incidental layout.
- **Docs follow the code** in the same change: README (user-visible behaviour), this file (architecture facts, rules), `tests/emu/README.md`, `loader/flash/README.md`. Keep them current, not historical; history is in git.
- **Commits:** conventional style (`feat:`, `fix:`, `docs:`, `ci:`, `refactor:`), one topic each.

## 2. Toolchain and code rules
- `arm-none-eabi-gcc`, `-march=armv5te -mthumb -mthumb-interwork -mbig-endian -Os`, freestanding (`-nostdlib -fno-builtin -ffreestanding`), `-Wall -Wextra` clean. ARMv5TE, ARM946E-S-class, MPU, **Thumb-1 only**: no `movw/movt`, `it`, `cbz`, `.w`, `dsb/isb/dmb`. `make audit` checks the ELF attributes.
- **No libgcc:** no `/` or `%` on runtime values; use `udiv32`/`put_udec` (`include/gr2_fmt.h`) or loops.
- **Logging:** `ERR*` always (literal text, prefixed `ERROR`); `DBG*` compiles out of release/rom and does not evaluate its arguments. Refusals and failures use `ERR`, everything else `DBG`. A release session writes nothing on success.
- **Addresses** live in `include/gr2_hw.h` with the finding that verified them. Thumb function pointers have bit 0 set; kernel (µITRON) calls are ARM-state, called through a pointer without bit 0 (finding 26 §2).
- **Tasks run in USR mode** (CPSR `0x60000010`): no CP15 (no cache maintenance), no IRQ masking. MPU region 5 allows USR writes to RTOS code and data. `Task_Create` never returns 0 (its assert parks the caller). CFW tasks block most of the time at `0x96`; CPU-heavy work belongs at `0xC0–0xD0` (finding 26 §3.3).
- **Task stacks:** any task that calls the stock file API needs ≥ 0x3000 (File_Open alone uses up to ~9.3 KB including the SD driver, finding 31); a too-small stack silently overwrites heap blocks. The emulator's file stubs check the stock need against the calling task's stack (`tests/emu/machine.py` `STOCK_FILE_STACK`); give new tasks and new call paths a task context there.
- **Code patches:** verify the original bytes first; each patch is one aligned halfword store, so a stale I-cache line can only hold the complete old instruction. BL retargets change only the first halfword and land on fixed-address veneers that share the stock target's low 12 bits. Patches applied at load time (stage 2's `cfw_hook`, before a section first runs) are not limited to one halfword.
- **Data patches** (tables, pointers, properties) verify first, record the stock value and restore it on STOCK / disable. Property writes go through the stock setter with values the stock menu can offer; read stock values with `Prop_Get_Raw` (`0xA00E0E81`, no getter hook). Property IDs ≥ `0x383` assert (finding 25). Persisted values must be stock-legal: a stock boot must accept everything the CFW saved.
- **Memory:** only stage 1 lives in the 32 KiB window `0xA0017000`; stage 2 and buffers come from `Memory_Alloc` (GlobalHeap, 2 MB shared with stock: single blocks well below ~200 KB). The boot pool is used up; `0xA0700000`+ is RTOS data.
- **Stage 2 is position-independent** apart from absolute 32-bit words: `scripts/mkmain.py` links it at 0 and `0x10000000` and fails on any other difference.
- **Speed:** nothing may slow the start. The release reads only NAND (A:, D:) in the boot hooks; the card is touched only after the camera's own mount.
- **Files on the card:** TTL and recipe files ASCII with CRLF, 8.3 recipe names, uppercase drive letters (`package_sd.py` checks).
- **Flash images:** only APP (type 1) and RES (type 2), built by script from the stock `.frm` with every stock byte asserted and `gr2frm.py verify` passing; stock bytes are never shifted. Never IPL/BAK, never `fe`/`fbe`/`fd`: they are the only recovery.

## 3. Load paths
- **Release firmware (`rom` variant, `loader/flash/rom_stub.S`):** `rg2_v003.frm` = stock 3.00 + the 132-byte stub in APP + the CFW files appended to the RES `A:` drive (`scripts/rom_files.py`: stage 1, stage 2, fonts). The stub loads `A:/cfw/gr2_cfw.bin` at the section-3 load with `LoadFile` (no mount, so no-card, USB and playback boots behave alike); stage 1 reads `A:/cfw/gr2_main.bin`. User files (recipes, config copy) come from the card's `cfw/` folder in the task's late phase. Design and checks: `loader/flash/README.md` §5.
- **Debug loader (`ldr_stub.S`, development):** the same stub reading stage 1 from `H:/cfw/gr2_cfw.bin` (the card is mounted at section 3, after JobSystem step 4 has started the lens: any card access earlier makes the lens bounce, finding 33).
- **Both:** stage 1 carries the loader ABI v1 header (`b` at +0, "GRL1" at +4, `cfw_ldr_hook` at +8, length +12, CRC-32 +16). The stub calls stage 1 after every APP section load n, in the boot task (stack 0x4000), before section n runs. The first hook checks the header, runs the safe-boot decision, preloads stage 2 and calls stage 2's `cfw_hook(n)` (second header entry); later hooks call `cfw_hook(n)`: config + slot looks at the first hook; the IQ-ready BL at hook(5), where CapInit(5) then applies the CFW settings and the slot's look before live view (findings 32, 35); menus/hooks/input, Snap labels and the CFW task at hook(10). The task runs in phases (APP after step 10, fonts after the card remount, late phase after `cfw_main`). hook(13) starts the `CFWldr` task (stack 0x4000), which waits for JobSystem step 13 and calls `cfw_main`. **Hook rules:** no card access before section 3 (release: none in the hooks at all), no H: writes before step 13 (the boot task remounts H: after hook(9); logs are held in RAM by `cfw_log_hold`), close every file before returning, nothing slow while live view runs, nothing that needs a later section or a running CFW task; settings and looks belong to the boot task until `cfw_main` has run, then to the CFW task. Details: `loader/flash/README.md` §3, findings 32, 33, 35.
- **SD loader (stock cameras only):** `loader/Startup.ttl` runs `fload H:/cfw/gr2_cfw.bin A0017000 8000` and `ex 0xA0017001` (needs `PROPID_DEVEL_MODE = 1`); `cfw_main` then runs in the Script task. Never on a loader camera: the `fload` rewrites the running stage 1 before `ex` refuses (`*0xA00AFD70` = 5/6). The emulator boots both ways.

## 4. Source map
- `src/entry.S`, `src/boot.c`, `include/boot.h`, `gr2_boot.ld`: stage 1 (window canary, stage-2 loader/relocator, loader ABI hook; header +12 length / +16 CRC-32 written by `scripts/stage1_crc.py`, checked at the first hook before anything else runs: on a mismatch ERROR into the RAM hold buffer, `ldr_state` = 6, nothing loaded). The rom build reads `A:/cfw/gr2_main.bin` with two `LoadFile` calls (stage 2 runs 32 B into its block). `.bss` must end below the power-off veneer `0xA001D1D4`; the IQ-ready, press and hold veneers are at `0xA001DA80`/`0xA001E07C`/`0xA001EEA0` (linker asserts).
- `include/safeboot.h` (finding 30 §1.5): state in RTC OPSR bits 2–3 (`sb_get`/`sb_set`). Stage 1's `safeboot()` (first loader hook, before stage 2 is read): ARMED → ONE_FAIL → DISARMED (both still run the CFW), DISARMED boots stock until a PLAY power-on (`UI_MODE` 2/3), STOCK_ONCE gives one stock boot; a session ended by the power-off job (`*0xA00C22DC == 1`) counts as healthy. The CFW task marks healthy after 20 s (only from ONE_FAIL); DEV "Boot stock once" sets STOCK_ONCE. RTC invalid → fail-open.
- `src/main.c`, `gr2_main.ld`: stage-2 entries: `cfw_hook(n)` (loader hooks, IQ-ready call, boot phases `cfw_phase_card`/`cfw_phase_late`, debug hook timeline) and `cfw_main` (log release, shell command, whatever the hooks did not install or start; installs run once). **rom (`CFW_ROM`): no card access in the boot hooks**: the first hook loads the config from D: only, and without one there `settings_early` is skipped (the task's late phase then imports the card copy and applies it).
- `src/task.c`, `include/cfw.h`: the "CFW" task: `cfw_task_poll` every 20 ms (event/key poll, INFO, overlays, 1 s heartbeat; fonts once the card is readable, rom from A: at the same point; late phase: `settings_init`, recipe scan, 200 ms settings/look polls). Menu requests stay pending until their menu can open.
- `src/shell.c`: `cfw` shell command, appended to the shell registry (`0xA05FC308`: +4 list, +8 count).
- `src/menu.c` (finding 16): "CFW Menu" (`0x1A6 = 0x20`, `0x1A7 = 2`) and "Recipes" (`0x21`, `3`) in the Effect menu records; the 21 language tables plus attribute/style tables are copied to the heap up to ID `0x35F` and the six string-accessor bounds raised to `0x360`. On a stock boot the saved choices act as "Off" (press) and "Wi-Fi" (hold).
- `src/hooks.c`, `src/veneers.S`: Effect press (`0xA03A1F92`) / hold (`0xA03A5790`) BL retargets; never patch the `cmp/bhs` at `0xA03A1F9A`. `0xA03E9984` is a guard-predicate slot and `0xA043DC32` playback data, not menu choices. Debug builds also log the session state from a power-off hook (`0xA00E9950`).
- `src/input.c` (finding 17): APP message handler pointer `0xA04071F0` swapped for a pass-through; consumes key messages only while captured, and only releases of presses it took; POWER is never taken, the shutter closes the overlay.
- `src/osd.c`, `include/osd.h` (finding 17): draw lock `0xA077D58C`, private back buffer on layer 3 (`0xA00D717F`); GFNT fonts from `H:/cfw/fonts` (rom: `A:/cfw/fonts` by `LoadFile`; ROM-font fallback), anti-aliased against the pixel below, threshold on translucent backgrounds. Palette entries 224–251 are overlay-owned while open (`osd_pal_user(k, r, g, b, alpha)`; the setter writes only the hidden bank, so `osd_pal_commit` flips and writes both). **Palette rule:** program and commit overlay entries before drawing pixels that use them; `osd_close` makes those pixels transparent before restoring the entries (otherwise they flash in the stock colours).
- `src/ui.c`: CFW Menu (tabs, settings rows grouped by function, INFO/DEV pages; OK toggles two-value rows only) and the Recipes filmstrip: `STRIP_GAP` above the bottom of the live-view image (`GR2_LV_ASPECT`: 3:2 ends at y 452, 16:9 at 420), translucent film base (entry 20, alpha 11), swatch slot = recipe index mod 5 (entries 0–19), names wrapped to two lines, shadow band only while choosing a slot or showing the result. Runs only in the CFW task.
- `src/settings.c`, `include/settings.h` (findings 18, 21, 35): property settings (Clarity `0xCE`, Auto-High Tv `0x113`, NR `0xEF`/`0xF0–0xF2`) with recorded stock values, re-applied ~1 s after a mode / MY-slot change (`settings_camera_value`: the recorded camera value while an override holds the property); RAM patches (TAv cap at AE_F+0x132; Auto ISO slowest/max at AE_F+0xBE/+0xC4/+0xC2/+0x2C8, keep shutter at +0xCA and +0xCC, stock in Movie; snap tables/literals/code halfwords; getter halfwords `0xA00DC236` TAv minimum and `0xA00DC22A` Auto ISO in M), all verify-first with reverse undo. `settings_early` applies them at the IQ-ready call (needs AE_F loaded and the mode props final), `settings_labels` after the menu install; `settings_init` then only labels and saves. Never run the stock `aeFSave` while AE_F overrides are active.
- `src/config.c`, `src/store.c`, `include/store.h` (finding 34): the config (`key=XXXXXXXX` hex lines, CRLF) on `D:/CFW/CFG_A.DAT`/`CFG_B.DAT`, written only when changed, into the older of two CRC'd generations (`store_save`), plus a backup copy `H:/cfw/config.txt` when the card is there (`cfg_sync_card` rewrites it in the late phase when missing or different); the card copy is loaded only when D: holds no valid config (stock formats D: on the first boot after a battery pull or crash, finding 34 §11; rom: only in the task's late phase, `cfg_load(card)`). `src/recipes.c` keeps the MY-slot looks the same way (`LOOK_A/B.DAT`). Only the CFW task writes; the loader's first hook reads.
- `src/recipes.c`, `include/recipes.h` (findings 18, 19): scan and parse recipes (`A:/cfw/recipes/` first in the rom build — empty in the shipped firmware —, then `H:/cfw/recipes`; a card file with the same 8.3 name replaces an A: one; A: `FindFirst` is a raw prefix returning full paths), plus the built-in "Stock" entry, always last; write a recipe into a MY slot file, remember the recipe per slot (config `rcK.0..2`, upper-case 8.3 name), choose the shown look (preview → active slot → stock). rom: `recipes_early_load` uses the D: look cache only. `recipes_format` is the parser's inverse (property values → keys, for the export): it writes a key only with a value `recipe_props` turns back into exactly the value read, anything else as a `#` comment; a new key needs both directions and the README table. "Stock" resets every property a key can set (`STOCK_IDS`).
- `src/export.c`, `include/export.h` (finding 19 §1.1/§5): DEV "Export settings to card" and the console `export`: MY1–3 and Box 1–6 (`B:/P_MY0k.bin`, `P_BOX0b.bin`; found with `File_Open` first, as `Property_LoadFile` falls back to the defaults silently) read through a clone of the live DB that is freed, never saved; the live settings by `Prop_Get_Raw`, except where a CFW Menu override is in force (`settings_camera_value`: the camera's value it replaced); Setting1/2 always and changed effect sliders from the live settings, or `B:/P_COMMON.bin` while the dial is on MY. One recipe file per preset in `H:/cfw/export/` (not scanned), 4 KB heap buffer allocated by the first export. Runs only in the CFW task: the console posts a request, `export_poll` (late phase) runs it while `CFWcon` waits in `Task_Delay`.
- `src/look.c`, `include/look.h` (finding 20): first use copies the matrix/hue/tone/YCbCr sections to the heap (~170 KB); a look writes CFW records (matrix 11, hue 6, tone 30–32, YCbCr 34–51) and repoints one IQ mode's list entries. Every write holds the ISP mutex and flips the ISP-Pre change cache (`0xA06C8B9A`, `0xA0155D20`); any new IQ stage must do the same.
- `src/overlay.c`, `include/overlay.h` (finding 23): VIEW frame lines and zebras in the RGBA4444 full plane (`BITMAPS[G[1]]`, `G` = `0xA04070AC`) while LCD, plane-mask bit 1, system mode 6/9 and layer 2 on; restamped 40 ms after every flip; `wipe()` + `REC_RGB_REDRAW` (`0xA0424360`) hands the plane back to stock. Zebras poll LV luma every 100 ms in 4×4 cells.
- `src/info.c`, `include/info.h` (finding 21): INFO getters; DEV actions (screenshot in 48-row bands from the shown LV frame + OSD, IQ dump, recipe rescan, preset export, overlay diagnostics 1.5 s after the menu closes, "Boot stock once"). A page shows 10 rows at a time (`MAX_ROWS` in src/ui.c; longer INFO/DEV pages scroll with the cursor; Wi-Fi name and password share one). Switch rows show OFF / ON (console, with reachability) or OFF / RUNNING / ON (test pattern). Wi-Fi is left to the camera menu: `Prop_Set(0x1E8)` + `Msg_Post(0x116)` reached JOBID_WIFI but no access point appeared; the stock menu also posts `0x10C` (finding 26 §4).
- `src/console.c`, `include/console.h` (finding 21 §3.2/§5): telnet console on port 23 (the stock telnetd is never started), task `CFWcon` created once; `console_set(0)` closes the sockets from the CFW task and removes the printf hook (slot `0xA05FCCD0+0x44`, installed only if empty; it only copies bytes under the console mutex). 16 KiB ring with `cfw_log_tap`. `console_exec` is the testable dispatcher; unknown words run as stock shell commands; `mem` is bounded to DRAM; `export` asks the CFW task (src/export.c) and waits up to 30 s.
- `src/log.c`, `include/cfw_log.h`: append-only `H:/cfw/cfw_log.txt`; `cfw_log_hold`/`cfw_log_release` buffer lines in RAM while the card must not be written (per stage; stage 2 keeps one 2 KiB buffer for the CFW task, chosen by its stack, and one for everything else). `src/mem.c`: `memset`/`memcpy` for compiler calls. `src/arm.S`: CPSR read.
- `loader/`: `Startup.ttl` (SD loader for stock cameras); `probe/` window check (`scripts/check_probe.py`); `flash/` debug stub (`ldr_stub.S`), release stub (`rom_stub.S`), timing probe, rescue script (`rescue/backup.ttl`, shipped in the official zip), design and checks (`README.md`).
- `scripts/`: `package_sd.py` (zips, checks), `mkmain.py`, `stage1_crc.py` (stage 1's +12 length / +16 CRC-32 after objcopy, every variant; `check()` for the packagers and tests), `fetch_firmware.py`, `build_loader_frm.py`/`emu_loader.py` (debug loader `.frm` + independent check), `rom_files.py` (the A: file set of the release firmware: `rom_files(root)` → {A: path: bytes}), `build_cfw_frm.py`/`emu_release.py` (release `.frm`: RES with the CFW files appended to A: and a new directory; independent byte check + stock `up` search/install, A: reads, the stub and a stock reinstall run as stock code on a simulated NAND), `flash_kit.py` (`dist/flash/<step>/` card folders + STEP.md for hardware test steps), `loader_timing.py` (timing probe decoder), `make_fonts.py` (Inter / Barlow Condensed → GFNT at 13/15/18/18/22 px; `include/osd.h` FONT_*, `src/osd.c` FONT_FILE and the packager must match).
- `recipes/*.txt`: the shipped recipes. The film looks are fitted directly to spektrafilm simulations by the maintainer's fitting tool (not part of this repository; regenerate, do not hand-edit). Recipes from other sources (hand-written, other generators, converted LUTs) may ship when their licence allows redistribution; every file names its source and licence in its header comments. Licences in `recipes/licenses/`. Test recipes are built inside `tests/emu`, never shipped.
- `tools/gr2frm.py`: `.frm` container tool (format, checksum, `repack` with resized images in Ricoh's layout, A: parsing like the camera); the maintainer keeps a canonical copy outside this repository, so change both together.
- `tests/emu/`: Unicorn machine model (`machine.py`; A: drive from `rom_files()` for the rom variant), scenarios (`run.py`; the rom variant runs `rom` only), renderer (`render.py`); see its README.
- `site/`, `tests/site/`, `.github/workflows/pages.yml`: the GitHub Pages site (static, no build step, no external requests except the GitHub releases API): `index.html` (home, download via the releases API with a fallback to the releases page, install/recovery/FAQ from this README; keep them in step), `convert.html` + `js/core.js`/`worker.js`/`convert.js` (LUT → recipe fit in a Web Worker on an approximate Standard model, no Ricoh tables or IQ data), `js/release.js`, one `css/style.css`. `node tests/site/validate.mjs` (CI and the Pages workflow) checks the converter and the README recipe rules against `recipes/*.txt`.
